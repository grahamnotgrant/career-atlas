# Review and improve

Read `../SESSION.md` and `../stop-slop/SKILL.md`.

**Inputs:** current canonical records, full coverage/import notes, resume versions, events and user priorities.

1. Report dataset scope first: date range, sources covered, missing evidence and last reconciliation. Count discovered roles separately from confirmed applications.
2. Compare role families and resume versions with denominators and waiting time. Separate recent pending applications from known decisions. Small samples cannot establish which wording caused an outcome.
3. Trace rejection and interview events to sources. Preserve unknown stages. Distinguish explicit employer feedback, user reports and hypotheses.
4. Review repeated company applications, offers and compensation details. Avoid double-counting one application across multiple geographic listings.
5. Select one useful next improvement: a targeting change, resume revision or focused evidence/interview session. Use the user's actual weak spot to choose questions.
6. Update the visual through its local interface when that helps explain the finding. Keep the underlying records intact.

**Outputs:** private dated analysis with record IDs, denominators, limits, source links and one next experiment or evidence session.

**Approval gates:** User approval for changed template claims/positioning or expanded application scope. Analysis does not create application authorization.

**Completion checks:** Counts reconcile to canonical records; missing data is explicit; conclusions do not turn silence into rejection or correlation into causation; improvement has a concrete check and follow-up date.
