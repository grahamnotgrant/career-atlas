# Run the search

Read `../SESSION.md`, `../stop-slop/SKILL.md` and `../../docs/WORKFLOW-CONTRACTS.md` (Permissions, Materials, App and verification). Complete Common startup in `../../docs/AGENT-START.md` once per run; reuse a daily parent's bounded sync/handoff rather than restarting it.

**Inputs:** selected opportunity IDs or existing queue, fresh preferences/grants/claims, approved matching templates and claim/source map, available form tools and relevant sync coverage.

1. Read fresh records and inspect the selected queue. Resolve relevant prior uncertain attempts against employer evidence before retrying. Request `../scout-roles/SKILL.md` only when discovery is needed; receipt-backed history and other owners' work stay intact. Completion: each selected role has a canonical identity, current lifecycle and explicit eligibility or dependent blocker.
2. Read the full employer posting. Check duty-level fit against supported experience, pay basis/floor, location restrictions, company history/limits and duplicates; preserve user holds/skips. Record `vet` checks. Completion: passing candidates have source-backed checks, and failed/unresolved candidates have reasons rather than inferred eligibility.
3. Verify an existing valid grant covers the exact role and claim it through the API. Retain owner, fence, grant and expiry; renew before expiry during preparation. Completion: the owned lease and active authorization are current. A lost lease stops that attempt while other eligible work continues.
4. Tailor from the approved matching template and source map, run the writing/document checks, and obtain missing unsupported/sensitive answers one at a time. Refresh experience evidence only for a real gap; pending new claims remain outside this application. Completion: material facts/wording stay within approval and the form can be answered truthfully.
5. Fill and inspect the employer form. Build the final Materials archive: every original question/exact answer or intentional omission, resume/manual text, supplemental upload/link and populated snapshot. Compare it field by field and stage exact hashes. Publish/read back the typed workspace material inventory for this exact attempt under the shared Materials contract. Call `prepare` with the final archive/material hashes and answers/reference; a later answer/file change requires a new final archive and prepare. Completion: the preserved inventory matches the final populated form and current approved template.
6. Immediately re-read grant scope/revocation/expiry/cap and claim ownership; renew the lease before the attempt when needed. Call `begin-submit` just before the external submission, follow applicable tool/user gates, then submit once. Renewal is unavailable after `begin-submit`. Completion: observed success/receipt, a supported block or an explicit uncertain result is captured; a timeout is not permission to retry.
7. Record `confirm` with receipt/archive evidence, or `result` for blocked/uncertain while the owned lease is still valid. If the lease has expired, `result` and `release` cannot complete: preserve the outcome privately and as sourced `annotate` provenance where supported, leaving the canonical lifecycle `attempted`. Confirm a later receipt without retrying the form, or use `reconcile` only after evidence proves non-submission. Keep submission confirmation independent of material coverage and read back identity, receipt, exact artifact links/hashes and the actual lease/lifecycle state. Completion: each attempted role has a source-backed outcome or explicit interrupted-attempt recovery item; owned leases are completed, released while valid or naturally expired without claiming an unsupported state change.
8. Refresh only new relevant source changes since the run's sync, then verify canonical writes and export independently. A daily coordinator owns the shared final handoff; standalone runs save it themselves. Completion: confirmed/uncertain/blocked counts, changed IDs, archives, coverage, questions and one next action are recorded.

**Outputs:** final application archives, source-backed application outcomes, canonical associations, settled claims, source checkpoints and separate export verification.

**Approval gates:** Apply the shared Permissions contract. Existing valid grants permit eligible submissions without another per-role approval. New claims, scope changes, sensitive/unsupported answers and required tool gates retain their own approvals; recruiter mail or timed assessments require relevant authorization.

**Completion checks:** every submission result has observed evidence; final questions/uploads match the preserved archive; receipt and exact materials reference the same identity/attempt; API readback/export are separate; uncertainty stays unresolved until reconciled, and role-specific blockers do not stop unrelated authorized work.
